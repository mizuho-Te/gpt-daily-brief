# Dots Daily Brief Kit

**GitHub の更新を、毎朝読む短い報告に。Dots にこのリポジトリを読んでもらい、設定確認から始める導入キットです。**

URL を渡すだけで勝手に実行・認証・定期配信するソフトではありません。Dots が手順を読み、利用可能な機能を確認し、あなたの承認後に設定します。利用環境に接続機能や自動化機能がなければ、設定案と手動プレビューまでです。

## Dots に送る依頼文

「このリポジトリの INSTALL_FOR_DOTS.md に沿って、公開 GitHub の日次まとめを設定して。まず使える接続機能を確認し、不足している設定だけ質問して。サンプルで試し、実データのプレビューを見せてから定期通知の承認を取ってください。外部サービスへの送信や認証追加は勝手にしないでください。」

この文にこのリポジトリの URL を添えてください。API キーを貼り付ける必要はありません。既に利用できる Dots の接続機能を使う設計です。Dots の利用プラン・接続先条件は別途必要です。「無料」「全環境で動作」とは保証しません。

## できることと現状

- 導入手順：接続機能確認 → 足りない設定だけ確認 → プレビュー → 承認 → 利用可能な公式自動化機能で設定 → 設定結果を確認。
- 最小版の対象：公開 GitHub リポジトリの issue / PR 更新。通知先は依頼中の本人とのチャット。
- ローカル検証：設定チェック、合成イベントの差分抽出、重複防止、失敗時に状態を進めない動作。
- **未実施**：実際の GPT 要約、ライブ GitHub 取得、Slack 連携、定期通知の作成・発火。実装コードは自動化の実行サービスではなく、設定検証と安全な差分処理の参考実装です。
- Slack などへの拡張は別途、対象データ・送信先・権限の確認が必要です。この版は Slack アダプターを含みません。

## 開発者向けの再現

Node.js 24、npm を使用。依存は package-lock.json で固定。

    npm ci
    npm run typecheck
    npm test
    npm run demo

demo は外部通信しません。2 件の合成更新を表示し、配信済み扱いをシミュレートした 2 回目は 0 件になります。障害を「更新なし」に変換しない例も表示します。これは GPT が要約した結果でも、実配信の証拠でもありません。

## なぜ作ったか

Anthropic の [Building effective agent automations](https://claude.dev/blog/building-effective-agent-automations/) にある日次まとめ・継続状態管理の考え方を参考に、Dots で導入相談を始められる小さなキットとして独自に作りました。公式製品・提携製品ではありません。記事や実装を丸ごと転載していません。

OpenAI の提供形態・条件は [公式ドキュメント](https://developers.openai.com/api/docs/quickstart) を参照してください。本キットは Responses API を必須にせず、利用中の Dots の機能を優先します。

詳細は INSTALL_FOR_DOTS.md、config.example.json、VERIFICATION.md を参照。MIT ライセンス。
